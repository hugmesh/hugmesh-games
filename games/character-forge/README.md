# character-forge — the 3D character maker (Godot 4)

The Godot half of `hugmesh-character-forge-bff-api`: a turntable studio that
builds a stylized 3D character from a **Char3DConfig v1** dictionary (DESIGN §2)
and hands it to the host page over the `CharForge` JavaScript bridge. Pure
GDScript, GL Compatibility renderer, threads OFF — one WASM bundle that runs
inside the games portal, the Angular remote, and the Matrix chat room.

```
scripts/character_assembler.gd   CANONICAL rig assembler (other repos vendor a copy)
scripts/char3d_config.gd         parse/clamp mirror of the BFF validator
scripts/part_registry.gd         the basis registry + the licence gate
scripts/pack_library.gd          vendored packs -> registry entries
scripts/pack_mount.gd            mounting a model onto the rig (+ BYO import)
scripts/glb_loader.gd            runtime glTF loading + the mandatory fixup pass
scripts/vrm_ingest.gd            godot-vrm parse, MToon swap, in-file licence read
scripts/house_materials.gd       one toon shader + one 8x8 palette texture per avatar
scripts/lip_sync.gd              jaw / mouth-strip / VRM-viseme channels
scripts/studio.gd                the turntable scene controller + built-in editor UI
assets/packs/                    the vendored CC0/CC-BY models + lanes.json catalogue
tests/run_tests.gd               headless behaviour tests (real assertions)
```

## The two bases: procedural and mesh

Every one of the 29 head families renders **procedurally** — parameterized
primitives and lofted meshes, no asset needed. That is the default and the only
universal basis, and nothing about it changed when the packs landed.

On top of it, `CharForgeRegistry` resolves a family (or a body archetype) to a
`mesh` basis. When it does, the assembler does **not** load anything: it builds
the procedural avatar as usual and emits `mesh_basis_required`, and
`CharForgeMount` swaps the mesh in on top. A missing, broken or over-cap asset
therefore degrades to the parametric character, never to an empty stage.

Two mounts:

- **avatar** — the model IS the character; the procedural rig is hidden.
- **body** — the model is the body and the procedural HEAD survives, re-parented
  onto the loaded rig's head bone by a `BoneAttachment3D` created from code
  (never authored inside a GLB — imported attachments create phantom bones).
  This is the kemono hybrid: a CC0 humanoid body under our beast head, because
  no production-grade CC0 rigged anthro biped exists to buy.

An entry may also be a **composed set**: extra GLBs (`pieces`) skinned to the
same rig as its primary, whose meshes are re-parented onto the primary's
skeleton at mount time. That is how the four Quaternius modular outfits work —
body + arms + legs + feet (+ pauldrons) assembled into one character with no
Blender step, because all 65 skin binds resolve by NAME against an identical
bone list. A piece whose binds do not all resolve is dropped and reported
rather than added as a collapsed mesh. The outfit sets mount as bodies, so the
procedural head sits on top: the pack ships no head piece.

## Where the geometry comes from

| Source | How it is loaded | Why |
| --- | --- | --- |
| `assets/packs/**/*.glb` | `load()` — the editor already imported it into a PackedScene | no runtime glTF parse, no main-thread hitch, no runtime-mipmap bug |
| `assets/packs/**/*.vrm` | bytes → the vendored godot-vrm addon | no `.vrm` importer is registered in this project, so there is no PackedScene to load |
| a user's own file | the same byte path, from the browser | the bytes are parsed in WASM memory and never written to disk |

The export preset's `include_filter` therefore ships `assets/packs/*.json` (the
catalogue the runtime reads) and `assets/packs/*.vrm` (~12 MB — the honest cost
of the anime lane). `.glb` needs no raw bytes in the PCK.

## Materials and recolouring

One house toon `ShaderMaterial` per palette region, all sharing ONE runtime 8x8
palette `ImageTexture` per avatar, so recolouring is a 64-pixel image rebuild
that touches no material at all — and it reaches mounted meshes too, because
their surfaces are rebound to the same materials.

That rebinding only happens for packs whose material policy is `map`
(Quaternius, VRoid, Godette — flat-colour slots that map onto the 11 semantic
regions). Single-atlas packs (KayKit, 100Avatars, the Khronos Fox) keep their
vendor material and are reported as **not recolourable**: binding one baked
atlas to a flat house colour would paint the whole character one colour, and
saying so is better than rendering something wrong.

MToon never survives on a recolourable VRM — its behaviour on WebGL2 is
undocumented upstream, so the house shader replaces it (technique.md's fallback
plan).

## The catalogue

`assets/packs/lanes.json` is GENERATED by `tools/asset-pipeline/build-lanes.mjs`
from the hand-authored lane mapping plus the committed `pack.json` manifests;
the same run emits the frontend's `pack-catalog.generated.ts`, so the selector
and the engine can never drift. `CharForgePacks` reads it and turns an entry
into a registry basis.

**Licence discipline is code, not convention.** A mesh basis is rejected — and
the family stays procedural — unless the entry carries `licenseSpdx` on the
CC0/CC-BY/MIT allow-list plus `attribution`, `sourceUrl` and an ISO
`retrievedAt`. `tests/run_tests.gd` asserts all 42 entries pass that gate, that
every `glb` path exists on disk, and that an NC licence is still refused.

`hiddenMeshes` on an entry names glTF nodes to hide at mount time: KayKit ships
every weapon and shield of the pack inside each character file, so a knight
would otherwise arrive holding seven of them. The 26 names are measured from
the committed bytes and a test fails if one stops matching.

## Host bridge (`window.CharForge`)

In: `setConfig(json)`, `setExpression(label)`, `setOpenness(0..1)`,
`randomize(seed)`, `snapshot(w,h) → base64 PNG`, `setUiVisible(bool)`,
`listPacks() → JSON`, `setPack(key)`, `importModel(base64, fileName)`.

Out (assigned by the host): `onConfigChanged(json)`, `onPackChanged(json)`,
`onImportResult(json)` — mirrored on `lastConfig` / `lastPack` / `lastImport`
for late hosts. A `charforge-ready` CustomEvent fires once the interface is up.

`importModel` is the BYO slot. The bytes go into WASM memory and nowhere else;
the report that comes back carries the file's OWN in-file licence terms (title,
authors, licence, redistribution, credit) so the UI can show the author's terms
rather than implying ours.

## Build / test

```bash
GODOT=/path/to/godot make -C .. import      # parse every script, import resources
GODOT=/path/to/godot make -C .. test        # headless behaviour tests
GODOT=/path/to/godot make -C .. check       # per-script parse check
GODOT=/path/to/godot make -C .. export-web  # skips cleanly without export templates
GODOT=/path/to/godot ../../tools/asset-pipeline/verify.sh   # re-audit the packs
```

The tests are real assertions on computed values — sanitize clamping, per-family
rig distinctness, expression/jaw math, palette cell contents, the triangle
budget, and the whole pack path (catalogue → licence gate → mounted mesh →
recolour → BYO import and its refusal paths). They exit non-zero on any failure
and are excluded from the web export.
