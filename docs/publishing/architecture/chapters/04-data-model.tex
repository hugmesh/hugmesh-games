\chapter{Data model}\label{ch:datamodel}

PostgreSQL holds the canonical relational state. Cassandra is a
write-through cross-pod cache for movement events, an audit log for game
state transitions, and a session store for short-lived browser tokens.
Kafka + ClickHouse are the streaming-audit / telemetry side-channel
introduced by decision 021 — gated by \texttt{app.kafka.enabled} and off
by default in dev. Liquibase drives Postgres schema migration through 41
changelogs at the head of \texttt{main}; Cassandra schemas are
bootstrapped by an init container and ClickHouse tables by the
Kafka-engine + materialised-view DDL bundled in
\texttt{docker/clickhouse-init/}.

\section{R2DBC + JDBC coexistence}

Runtime data access is non-blocking R2DBC. Liquibase needs a blocking
JDBC \texttt{DataSource}, so \snapfile{JdbcDataSourceConfig} declares an
explicit \texttt{@Primary HikariDataSource} (pool size 3) just for the
migration phase. R2DBC then connects in parallel against the same
database via the \texttt{spring.r2dbc.url} property.

\begin{snapcaution}[title={MVCC snapshot race}]
\texttt{@PostConstruct} services that touch the database can run
\emph{before} Liquibase commits, locking their R2DBC connection into a
pre-migration snapshot. The fix in this codebase is \texttt{@DependsOn(\"liquibase\")}
on \snapfile{GameTimeService} and \snapfile{GameStateService}, plus
\texttt{spring.r2dbc.pool.initial-size=0} in tests so the pool only opens
connections after Liquibase finishes. Without these, the symptom is
\texttt{BadSqlGrammarException: relation does not exist} from a query
the test fixture clearly sets up.
\end{snapcaution}

\section{Cassandra cache}

The Cassandra keyspace holds:

\begin{itemize}
  \item \textbf{Movement events} — write-through buffer for
        \texttt{ControlEvent}s; the SSE stream reads from Postgres but
        Cassandra holds the recent N events for fast cross-pod replay.
  \item \textbf{Audit log} — every state transition emitted by
        \snapfile{GameStateService} is persisted with
        \texttt{(character\_id, occurred\_at)} as the primary key.
  \item \textbf{Session store} — short-lived per-tab tokens bound to a
        Casdoor user, used by the BFF to refuse \texttt{/api/controls}
        requests from a tab that's not currently the controller for the
        target session.
\end{itemize}

A nightly \snapfile{CassandraSyncService} reconciles audit-log totals
back into Postgres counters so dashboards stay consistent across reboots.
Decision 021 introduces the Kafka $\rightarrow$ ClickHouse streaming
pipeline as the long-term replacement; \snapfile{CassandraSyncService}
stays in place until the streaming pipeline has demonstrated production
stability.

\section{Streaming audit / telemetry pipeline (Kafka + ClickHouse)}

Decision 021 introduces a streaming side-channel that runs alongside the
in-process gameplay path without changing it. Gated by
\texttt{app.kafka.enabled} (default \texttt{false}) so vanilla
\texttt{compose up} keeps the slim path. Four Kafka topics:

\begin{tabularx}{\linewidth}{l l X}
\toprule
\textbf{Topic} & \textbf{Producer} & \textbf{Purpose} \\
\midrule
\texttt{state\_audit} & \snapfile{GameAuditPublisher} & Every state
transition emitted by \snapfile{GameStateService} --- durable
replacement for the Cassandra audit log. \\
\texttt{game\_events} & \snapfile{GameEventPublisher} & All 8 SSE
channels (movement / world / character / scene / input / audio / view /
wasm-console) tee'd from \texttt{GameStateService.tryEmitNext}. The
cross-pod consumer \snapfile{KafkaSessionSubscriber} filters
self-published via \texttt{pod\_id} and dispatches per-channel to
handlers registered in \texttt{GameStateService.@PostConstruct}. \\
\texttt{game\_kpi} & \snapfile{GameKpiPublisher} & Per-game KPIs posted
by federated game remotes via
\texttt{POST /api/telemetry/game/\{slug\}}. Iframes hit the BFF
directly under existing \snapfile{WebConfig} CORS allowlist. \\
\texttt{session.<id>.events} & \snapfile{SessionTopicManager} &
Per-session topics created on session-create so a cross-pod subscriber
can hydrate only the sessions it cares about. \\
\bottomrule
\end{tabularx}

\bigskip

ClickHouse consumes via Kafka-engine tables + materialised views
(\snapfile{docker/clickhouse-init/01-snapdragon-schema.sql}) that land
each topic in a durable MergeTree counterpart. The
\texttt{player\_state\_current} ReplacingMergeTree captures the latest
per-character state for session-reconnect recovery;
\snapfile{PlayerStateRecoveryService} queries it through the ClickHouse
HTTP interface from \texttt{GameStateService.hydrate(...)}, with
\texttt{Mono.empty()} as the expected miss path (SSE / gameplay never
blocks). Rolling KPI aggregates (\texttt{kpi\_rolling\_avg\_24h}) feed
admin dashboards.

\section{Postgres read replica (decision 022)}

Decision 022 adds an opt-in read-replica routing layer.
\snapfile{R2dbcReadReplicaConfig} provides
\texttt{@Qualifier("replica")} \texttt{ConnectionFactory} /
\texttt{R2dbcEntityTemplate} / \texttt{DatabaseClient} beans; when
\texttt{app.r2dbc.replica.url} is empty the replica beans alias the
primary so the route is transparent on single-DB stacks. The
compose-level pair lives in the opt-in overlay
\reposrc{docker-compose.replica.yml} --- both nodes run the existing
\texttt{postgres:16-alpine} image so the existing \texttt{pgdata} volume
layout is preserved; bring it up with
\reposrc{scripts/setup-pg-replica.sh}, which bounces primary with
\texttt{wal\_level=replica} + a replication role and the replica
\texttt{pg\_basebackup}s on first boot via
\reposrc{docker/postgres-replica-entrypoint.sh}.

\section{Generalised input event surface (Liquibase 026)}

The five legacy game tables (\texttt{characters}, \texttt{controls},
\texttt{spell\_loadout}, ...) cover JRPG-shaped gameplay; the input
surface added in changeset 026 covers \emph{everything Godot can
consume}: gamepad button / axis, mouse motion / button / wheel,
keyboard up / down, touch gestures, audio cues, world events,
plus the legacy control commands as one kind among many.

Three reference tables anchor the schema; an append-only audit
table writes against them.

\begin{tabularx}{\linewidth}{l X}
\toprule
\textbf{Table} & \textbf{Purpose} \\
\midrule
\texttt{input\_event\_kinds} & Reference. Primary key on
\texttt{kind}. Closed vocabulary of input categories: \texttt{gamepad},
\texttt{mouse}, \texttt{keyboard}, \texttt{touch}, \texttt{audio},
\texttt{world}, \texttt{control}. Seeded by Liquibase 026. \\

\texttt{input\_event\_types} & Reference. \textbf{Composite}
primary key \texttt{(kind, type)}. Per-kind type vocabulary
(\texttt{gamepad: button\_down / button\_up / axis / connected /
disconnected / rumble\_ack}, \texttt{mouse: motion / button\_down /
button\_up / wheel}, ...) plus an \texttt{example\_payload} (jsonb)
used by the upload-time validator and the OpenAPI explorer's sample
generator. \\

\texttt{game\_event\_support} & Per-game opt-in. \textbf{Composite}
primary key \texttt{(game\_slug, event\_kind, event\_type)}, FK to
\texttt{input\_event\_types(kind, type)}. The Snapdragon Export
plugin writes one row per declared event during upload; the BFF
refuses any input emit whose triple isn't enabled here, regardless
of what the client sends. \\

\texttt{input\_events} & Append-only audit log. FK on
\texttt{(event\_kind, event\_type)} into
\texttt{input\_event\_types} so a row can never reference an
unknown type. Indexed on \texttt{(character\_id, occurred\_at)},
\texttt{(session\_id, occurred\_at)}, and
\texttt{(event\_kind, occurred\_at)} for replay + analytics. \\

\texttt{games.features} & New \texttt{jsonb} column. Per-game
feature flags: \texttt{spell\_loadout}, \texttt{quests},
\texttt{items}, \texttt{char\_progression} (the JRPG subsystems —
non-JRPG games turn these off and the matching endpoints return
\texttt{405}); \texttt{audio}, \texttt{gamepad}, \texttt{mouse},
\texttt{keyboard}, \texttt{touch} (input-kind gates — a game with
\texttt{gamepad: false} can't accidentally write gamepad rows). \\
\bottomrule
\end{tabularx}

\bigskip

The validation flow on every input emit is three gates:
\begin{enumerate}
  \item \texttt{(kind, type)} must exist in
        \texttt{input\_event\_types} (400 if not).
  \item \texttt{games.features.<kind>} must be true
        for the active game (405 if not).
  \item \texttt{(game\_slug, kind, type)} must be present in
        \texttt{game\_event\_support} (405 if not).
\end{enumerate}

Same surface persists every browser-tier gamepad poll, every
WASM-iframe console line forwarded by the host shell, every
audio cue the Godot bundle emits. The Rust GDExtension's
\texttt{HostBridge} ships matching typed signals
(\texttt{gamepad\_received}, \texttt{mouse\_received},
\texttt{keyboard\_received}, \texttt{touch\_received},
\texttt{audio\_received}, plus outbound \texttt{audio\_egress} and
\texttt{console\_egress}) so a Godot developer wires gameplay to
named signals without caring whether the source was a player's
USB Pro Controller, a \texttt{<kbd>W</kbd>} keypress, or an SSE
emit from a cross-tab subscriber.

\section{Per-game mod / publisher scopes}

Mod and publisher authorisation is split intentionally:

\begin{itemize}
  \item \textbf{Casdoor} owns ``is a mod / publisher at all'' ---
        \texttt{ROLE\_MOD} / \texttt{ROLE\_PUBLISHER} claim membership.
  \item \textbf{Postgres} owns ``for which games'' ---
        \texttt{mod\_game\_scopes} (Liquibase 032) and
        \texttt{publisher\_game\_scopes} (Liquibase 033) each hold one
        row per (casdoorId, gameSlug) pair.
\end{itemize}

The BFF reads both layers for every mod- or publisher-only mutation. A
Casdoor token alone authenticates the request but doesn't authorise it;
the Postgres row provides the per-game gate. Identity-provider replacement
(Auth0, Cognito, Entra) carries the role membership but the per-game
scope stays in the relational store.

Mutation endpoints follow a strict admin / publisher split. Only
\texttt{/api/admin/role-grants/*} (admin) and
\texttt{/api/publisher/grant-mod} (publisher within scope) write rows;
everything else is read-only.

under \snapfile{rpg-builder/src/main/resources/db/changelog/} and
\snapfile{vn-builder/src/main/resources/db/changelog/} --- managed by
Liquibase end-to-end (no JPA \texttt{ddl-auto}, no psql-init seed).

\begin{itemize}
  \item \snapfile{postgres-rpg-builder} --- areas, rooms, exits, items,
        NPCs, scripts. Mudlet-shaped.
  \item \snapfile{postgres-vn-builder} --- acts, characters, backgrounds,
        scenes, dialogue lines, branching choices. godot-2d-visual-novel-
        shaped.
\end{itemize}

Each side service's build worker walks its project tree, renders a
Godot 4 source tree (with \snapfile{snapdragon\_bridge.gdextension}
baked in), invokes the Godot CLI per area (RPG) or act (VN), zips the
result, and POSTs to the BFF \texttt{/api/admin/games/upload}
endpoint with the originating user's bearer token, so the BFF's
existing \texttt{publisher\_game\_scopes} check enforces who can ship
which slug.

Each area / act becomes a Chapter row in the BFF's \texttt{chapters}
table on upload. The three Postgres instances live in the same compose
stack today but have nothing in common at the schema level; cloud
relocation can move them independently. Decision 018 has the full
shape.

\section{Identity widening (Liquibase 036)}

\snapfile{Crypto.mintUid()} replaced \texttt{UUID.randomUUID()} for
every UI-facing UID and URL token. Output: 43-character URL-safe base64
of \texttt{SHA3-256(64 random bytes from BouncyCastle SP800-90A
HMAC-SHA256 DRBG)}. Liquibase 036 widens session-id columns from
\texttt{varchar(36)} to \texttt{varchar(64)} to fit the new shape;
pre-existing UUID-shape rows (36 chars) continue to fit unchanged.
Cross-system joins on session id keep working because the migration
widens every join target in the same changeset.
