\chapter{API and service-tier reference}\label{ch:api}

This chapter is the printed companion to the generated Javadoc HTML at
\reposrc{docs/publishing/javadoc-output/index.html}. Every controller is
listed once with its endpoints, auth posture, and a one-line description
of the contract; every service / scheduled worker is listed in a
parallel section after the controllers. The Javadoc has the
per-method signatures, parameter descriptions, and full HTTP examples.
The Javadoc is rebuilt by \snapcommand{make docs-javadocs} and is
themed to match this document (see
\snapfile{docs/publishing/javadoc-theme/snapdragon.css}).

\bigskip

The reactive controllers and services below carry a \emph{marble
diagram} showing their Project Reactor chain. Marbles use distinct
shapes for distinct runtime types so the topology is readable at a
glance:
\snapmarbleshape{marbleMono}~\texttt{Mono<T>} value,
\snapmarbleshape{marbleFlux}~\texttt{Flux<T>} element,
\snapmarbleshape{marbleSSE}~\texttt{ServerSentEvent} (HTTP-tier emission),
\snapmarbleshape{marbleTx}~persistence-tier value (R2DBC row / post-tx),
\snapmarbleshape{marbleSig}~control / signal,
\snapmarbleshape{marbleErr}~error,
\snapmarbleshape{marbleDone}~\texttt{onComplete}. Each diagram's legend
lists the carried object's relevant fields and flags so a reader can
cross-reference the chain with the BFF source code.

\medskip

Every controller subsection follows the same shape: marble diagram
$\rightarrow$ legend $\rightarrow$ a worked \emph{call example} (curl
request, happy-path JSON response, and the most likely error response).
The error responses are the ones an integrator is most likely to hit;
exhaustive status-code tables are in the OpenAPI spec at
\snapfile{docs/publishing/openapi/openapi.fallback.json} (and at
runtime, at \texttt{/v3/api-docs}).

\section{Public surface}

\subsection{\texttt{AuthController} — \texttt{/api/auth}}
Public reverse-proxy of the Casdoor login flow.

\begin{itemize}
  \item \texttt{POST /api/auth/token} — exchanges a Casdoor authorization
        code for an access token; the federated \texttt{login} remote
        calls this directly.
  \item \texttt{GET /api/auth/me} — returns the resolved Casdoor user
        from the bearer token.
\end{itemize}

\snapdiagram{marbles/auth-controller.tex}
\snapmarblelegend{
  \snapmarbleshape{marbleMono} & \texttt{TokenExchangeRequest}
    & \texttt{code} (Casdoor authorization code) {\rm $\cdot$} \texttt{redirectUri} {\rm $\cdot$} \texttt{state} (CSRF echo). \\
  \snapmarbleshape{marbleSSE}  & Upstream JSON
    & raw Casdoor response: \texttt{access\_token}, \texttt{token\_type}, \texttt{expires\_in}, \texttt{refresh\_token}. \\
  \snapmarbleshape{marbleMono} & \texttt{TokenResponse}
    & decoded DTO: \texttt{accessToken}, \texttt{expiresAt} (Instant), \texttt{refreshToken}, \texttt{casdoorUserId}. \\
  \snapmarbleshape{marbleDone} & \texttt{onComplete}
    & terminal: a single value plus completion. The host writes it to \texttt{sessionStorage.tw\_auth}. \\
}

\paragraph{Call example.}
\begin{lstlisting}[language=bash]
curl -sS -X POST http://localhost:8080/api/auth/token \
  -H 'Content-Type: application/json' \
  -d '{"code":"abc123","redirectUri":"http://localhost:8080/login"}'
\end{lstlisting}
\textit{200 OK:}
\begin{lstlisting}[language=json]
{ "accessToken": "eyJhbGciOi...", "expiresAt": "2026-04-26T12:30:00Z",
  "refreshToken": "rt_abc123", "casdoorUserId": "alice@threewizards" }
\end{lstlisting}
\textit{400 Bad Request — Casdoor rejected the code:}
\begin{lstlisting}[language=json]
{ "status": 400, "error": "invalid_grant",
  "message": "Casdoor: authorization code expired or already used" }
\end{lstlisting}

\subsection{\texttt{GameStreamController} — \texttt{/api/game}}
Public SSE merge stream — eight typed channels plus a keepalive.

\begin{itemize}
  \item \texttt{GET /api/game/stream} — returns eight typed event
        channels (\texttt{movement}, \texttt{world}, \texttt{character},
        \texttt{scene}, \texttt{time}, \texttt{input}, \texttt{audio},
        \texttt{wasm-console}) plus a 15-second \texttt{keepalive}
        ping that fires immediately on subscribe so
        \texttt{EventSource.onopen} fires within milliseconds.
\end{itemize}

\snapdiagram{marbles/game-stream-controller.tex}
\snapmarblelegend{
  \snapmarbleshape{marbleFlux} & \texttt{PlayerMovement}
    & \texttt{characterId} {\rm $\cdot$} \texttt{x,y,z} {\rm $\cdot$} \texttt{rotationY} {\rm $\cdot$} \texttt{action} {\rm $\cdot$} \texttt{pressed} (bool) {\rm $\cdot$} \texttt{tick}. \\
  \snapmarbleshape{marbleFlux} & \texttt{WorldEvent}
    & \texttt{type} (\texttt{spawn}/\texttt{despawn}/\texttt{transition}) {\rm $\cdot$} \texttt{payload} (Map). \\
  \snapmarbleshape{marbleFlux} & \texttt{CharacterDto}
    & \texttt{characterId} {\rm $\cdot$} \texttt{hp,mp,xp} {\rm $\cdot$} \texttt{flags}: \texttt{stunned}/\texttt{burning}/\texttt{frozen}. \\
  \snapmarbleshape{marbleFlux} & \texttt{SceneEvent}
    & spawn / despawn / level transition events from \texttt{GameStateService.notifySceneEvent}. \\
  \snapmarbleshape{marbleFlux} & \texttt{GameTimeDto}
    & \texttt{day} {\rm $\cdot$} \texttt{hour} {\rm $\cdot$} \texttt{minute} {\rm $\cdot$} \texttt{phase}. \\
  \snapmarbleshape{marbleFlux} & \texttt{InputEvent}
    & \texttt{kind}/\texttt{type} discriminator pair {\rm $\cdot$} \texttt{payload} (jsonb). \\
  \snapmarbleshape{marbleFlux} & \texttt{InputEvent} (audio kind)
    & auto-routed off the same source whenever \texttt{kind == "audio"}. \\
  \snapmarbleshape{marbleErr}  & \texttt{WasmConsoleLine}
    & forwarded WASM-iframe error / warn — \texttt{level} {\rm $\cdot$} \texttt{message} {\rm $\cdot$} \texttt{stack}. \\
  \snapmarbleshape{marbleSig}  & ping
    & 15-second keepalive; first ping fires the moment subscription lands. \\
  \snapmarbleshape{marbleSSE}  & \texttt{ServerSentEvent}
    & merged downstream: \texttt{event} (the channel name) {\rm $\cdot$} \texttt{data} (JSON of source) {\rm $\cdot$} \texttt{id}. \\
}

\paragraph{Call example.}
\begin{lstlisting}[language=bash]
curl -N http://localhost:8080/api/game/stream
\end{lstlisting}
\textit{200 OK — text/event-stream (excerpt):}
\begin{lstlisting}
event: keepalive
data: {"ts":"2026-04-26T12:30:00Z"}

event: movement
data: {"characterId":1,"x":12.4,"y":0.0,"z":-3.1,"action":"walk","tick":4421}

event: time
data: {"day":3,"hour":18,"minute":42,"phase":"dusk"}
\end{lstlisting}
\textit{Client disconnects:} the underlying \texttt{Sinks.Many}
instances stay open (\texttt{autoCancel=false}). A reconnect from the
same client gets a fresh subscription on the same sinks — see
scenario~2 below.

\subsection{\texttt{GameController} — \texttt{/api/games}}
Public game catalog (filtered by \texttt{game\_access} when a JWT is
present). Composes with \texttt{ProgressionService} for
quest-completion-aware unlock state.

\begin{itemize}
  \item \texttt{GET /api/games} — list of all games.
  \item \texttt{GET /api/games/\{id\}} — one game by id.
  \item \texttt{GET /api/games/\{id\}/levels} — its levels by id.
  \item \texttt{GET /api/games/available/\{characterId\}} — JWT-aware
        availability list with per-game lock state.
\end{itemize}

\snapdiagram{marbles/game-controller.tex}
\snapmarblelegend{
  \snapmarbleshape{marbleMono} & \texttt{GET .../available/\{id\}}
    & inputs: \texttt{characterId} (path) + JWT (optional). \\
  \snapmarbleshape{marbleFlux} & \texttt{GameWithLevelsDto}
    & per-game DTO with \texttt{unlocked} bool {\rm $\cdot$} \texttt{levels: List<LevelDto>}. \\
  \snapmarbleshape{marbleTx}   & filtered + unlocked
    & only games whose \texttt{game\_access} row matches scope; \texttt{unlocked} from quest state. \\
}

\paragraph{Call example.}
\begin{lstlisting}[language=bash]
curl -sS -H "Authorization: Bearer $JWT" \
  http://localhost:8080/api/games/available/1
\end{lstlisting}
\textit{200 OK:}
\begin{lstlisting}[language=json]
[ { "slug": "three-wizards", "displayName": "Three Wizards",
    "unlocked": true,  "levels": [{"id": 1, "slug": "cave"}] },
  { "slug": "dodecahedron", "displayName": "Dodecahedron",
    "unlocked": false, "lockReason": "quest 'awakening' incomplete" } ]
\end{lstlisting}

\subsection{\texttt{AssetController} — \texttt{/api/assets}}
Public legacy classpath asset serving plus the launch-uid-gated
filesystem path for hot-uploaded bundles.

\snapdiagram{marbles/asset-controller.tex}
\snapmarblelegend{
  \snapmarbleshape{marbleMono} & request
    & \texttt{slug} {\rm $\cdot$} \texttt{uid} (path-var, optional) {\rm $\cdot$} \texttt{filename}. \\
  \snapmarbleshape{marbleTx}   & resolved \texttt{Resource}
    & 200 OK with \texttt{Content-Type} from a small extension map; bytes from filesystem or classpath fallback. \\
  \snapmarbleshape{marbleErr}  & 403 / 404
    & 403 when \texttt{app.assets.require-launch-uid=true} and the uid is missing/expired; 404 when the file resolves nowhere. \\

\paragraph{Call example.}
\begin{lstlisting}[language=bash]

\end{lstlisting}
\textit{200 OK} returns the bundle bytes. \textit{403:} \texttt{\{"error":"launch\_uid\_required"\}}; \textit{404:} \texttt{\{"error":"asset\_not\_found"\}}.

\subsection{\texttt{ControlController} — \texttt{/api/controls}}
Session-validated control event ingestion. The session check is enforced
through the JWT subject; the legacy \texttt{X-Casdoor-Id} header path is
gone.

\snapdiagram{marbles/control-controller.tex}
\snapmarblelegend{
  \snapmarbleshape{marbleSig}  & \texttt{ControlEvent}
    & \texttt{characterId} (path var) {\rm $\cdot$} \texttt{sessionId} (header) {\rm $\cdot$} \texttt{action} (\texttt{move}/\texttt{cast}/\texttt{interact}) {\rm $\cdot$} \texttt{x,y} {\rm $\cdot$} \texttt{pressed} (bool) {\rm $\cdot$} \texttt{spellSlot}? . \\
  \snapmarbleshape{marbleTx}   & persisted row
    & \texttt{controls} table: same fields plus \texttt{persistedAt} (Instant) and the unique \texttt{(characterId, sessionId)} constraint. \\
  \snapmarbleshape{marbleFlux} & sink emission
    & a copy of the persisted row pushed onto \texttt{GameStateService.movementSink} so every connected SSE subscriber sees it. \\
  \snapmarbleshape{marbleErr}  & \texttt{Forbidden403}
    & raised by \texttt{filterWhen} when the JWT subject isn't the controller-role holder for that session; never reaches the sink. \\
}

\paragraph{Call example.}
\begin{lstlisting}[language=bash]
curl -sS -X POST -H "Authorization: Bearer $JWT" \
  -H 'Content-Type: application/json' \
  -d '{"sessionId":"sess_8f3c1a","action":"cast",
       "x":12.4,"y":0.0,"pressed":true,"spellSlot":2}' \
  http://localhost:8080/api/controls/1
\end{lstlisting}
\textit{204 No Content} on success. \textit{403:} \texttt{\{"error":"not\_session\_controller"\}}.

\paragraph{Auto-recovery on 403.} A 403 from \snapfile{game_bridge.gd}'s
\texttt{send\_control} triggers a \texttt{SD\_SESSION\_EXPIRED}
\texttt{postMessage} to the host shell;
\snapfile{ApiBridgeService.handleSessionExpired()} re-runs
\texttt{session.connect()} $\to$ \texttt{session.claimControl()} so the
next keypress succeeds without a page reload. This makes a BFF restart
survivable while the Angular SPA is still mounted (the in-memory
\texttt{activeSessions}/\texttt{currentController} are wiped on restart,
but the SPA never sees the gap).

\subsection{\texttt{DiagnosticsController} — \texttt{/api/diagnostics}}
Anonymous endpoint for forwarded WASM-iframe console captures. Stamps a
server timestamp and pushes onto the \texttt{wasm-console} SSE channel so
admin docs explorers can mirror crashes live.

\snapdiagram{marbles/diagnostics-controller.tex}
\snapmarblelegend{
  \snapmarbleshape{marbleMono} & \texttt{WasmConsoleLine}
    & \texttt{level} (\texttt{error}/\texttt{warn}/\texttt{info}/\texttt{log}) {\rm $\cdot$} \texttt{gameSlug}? {\rm $\cdot$} \texttt{levelSlug}? {\rm $\cdot$} \texttt{message} {\rm $\cdot$} \texttt{source}? {\rm $\cdot$} \texttt{line}? {\rm $\cdot$} \texttt{stack}?. \\
  \snapmarbleshape{marbleErr}  & SSE: \texttt{wasm-console}
    & rendered as a \texttt{marbleErr} on the stream because subscribers usually treat these as failure events. \\
}

\paragraph{Call example.}
\begin{lstlisting}[language=bash]
curl -sS -X POST http://localhost:8080/api/diagnostics/wasm-console \
  -H 'Content-Type: application/json' \
  -d '{"level":"error","gameSlug":"three-wizards",
       "message":"RangeError: Maximum call stack size exceeded",
       "source":"/cave/index.js","line":1428}'
\end{lstlisting}
\textit{202 Accepted}; the stamped row appears on the
\texttt{wasm-console} SSE channel within milliseconds.

\subsection{\texttt{SessionController} — \texttt{/api/sessions}}
Session connect / disconnect / control-claim / history. Capacity is hard-capped

\section{BFF service tier}\label{sec:services}

The controllers above are thin: they decode the request, run a
reactor chain through one or more services, and return a DTO. The
real work lives in the services below. They hold the long-lived
\texttt{Sinks.Many} that the SSE stream merges, the \texttt{@Scheduled}
heartbeats / sweepers / pruners, and the transactional install pipeline
for hot uploads. Each carries its own marble.

\subsection{\texttt{GameStateService}}
Owns seven \texttt{Sinks.Many}: \texttt{movement}, \texttt{world},
\texttt{character}, \texttt{scene}, \texttt{input}, \texttt{audio},
\texttt{wasm-console}. Every sink is built with
\texttt{onBackpressureBuffer(N, /\,*\,autoCancel\,*\,/ false)} so a
disconnecting subscriber doesn't terminate the producer side.
\texttt{@DependsOn(\"liquibase\")} guarantees the \texttt{@PostConstruct}
init query runs against the migrated schema.

\snapdiagram{marbles/game-state-service.tex}
\snapmarblelegend{
  \snapmarbleshape{marbleFlux} & seven sink streams
    & one \texttt{Sinks.Many<T>} per channel — buffer size capped per channel and tuned in \texttt{application.yml}. \\
  \snapmarbleshape{marbleSig}  & \texttt{applyControl(...)}, \texttt{emitInput(...)}, \texttt{emitWasmConsole(...)}
    & public methods that controllers call to push a value onto the right sink. \\
}

\paragraph{Call example (caller side).}
\begin{lstlisting}[language=java]
// Inside ControlController:

  .flatMap(controlRepo::upsert)
  .doOnNext(e -> gameState.applyControl(e, characterId))
  .then();

unwinds, the R2DBC transaction rolls back, AND the on-disk move is
reversed. The prior \texttt{games.current\_version\_dir} is unchanged
and the active bundle keeps serving — see scenario 4.

\section{Example call scenarios}

The marbles above show the \emph{happy path} of each controller and
service. Production traffic also exercises four recurring non-happy
paths; each gets a dedicated marble below.

\subsection*{Scenario 1 --- Unauthenticated request}

\snapdiagram{marbles/scenario-error-401.tex}

A request arriving without a Bearer token, or with an expired one,
is rejected by the OAuth2 resource-server filter \emph{before} the
controller's reactor pipeline starts; the response is \texttt{401}
with no controller code touched. Watch this in the BFF log to tell
``client forgot to pass a token'' apart from ``token rejected by
JWKS''.

\subsection*{Scenario 2 --- SSE subscriber drops mid-stream}

\snapdiagram{marbles/scenario-sse-disconnect.tex}

The most common false alarm. A browser tab closes mid-stream; the
client TCP closes; Reactor sees \texttt{onCancel}; subscription~1 is
deregistered; \emph{the upstream Sinks stay open} because every
\texttt{Sinks.many()} in this project sets \texttt{autoCancel=false}.
A reconnect from the same client gets a fresh subscription against
the same Sink and keeps reading from the buffered window onward. If
this scenario stops working --- the symptom is "first reconnect, then
silence" --- the offending Sink lost its \texttt{autoCancel=false}
flag.

\subsection*{Scenario 3 --- Admin force-revokes (kicks) a launch}

\snapdiagram{marbles/scenario-admin-kick.tex}

\texttt{ROLE\_ADMIN} clicks \emph{kick} on the dashboard; the BFF runs
the \texttt{DELETE} inside a transactional block that sets
\texttt{game\_launches.terminated\_at = NOW()}. Bytes already in
flight to the player's iframe finish (the WASM keeps running on what
it already has); the kick lands at the next level-transition where
the player's request is denied with \texttt{410 Gone}. The host shell
catches the resulting \texttt{NavigationError} and shows a banner.

\subsection*{Scenario 4 --- Hot upload rolls back}

\snapdiagram{marbles/scenario-upload-rollback.tex}

The install transaction is the most fragile path in the system because
it commits across two stores --- Postgres (the games rows) and the
filesystem (the staged bundle directory). When \texttt{register.sql}
throws inside the transactional block, Reactor's \texttt{onError}
unwinds: the R2DBC transaction rolls back \emph{and} the on-disk
move is reversed before returning the response. The prior
\texttt{games.current\_version\_dir} is unchanged and the active
bundle keeps serving. Failure surfaces to the admin UI as
\texttt{500} (internal SQL exception) or \texttt{409} when the
exception carries a slug-aware reason (e.g. constraint violation on
\texttt{games\_pkey}).
