\chapter{Executive summary}
A multi-game browser portal. One Spring Boot BFF brokers reads and
writes for many concurrent games and players. Two stores, by
responsibility: PostgreSQL is the canonical relational state (catalog,
players, federation, access, uploads); Cassandra is a high-write log +
cache (movement events, audit log, short-lived sessions). Casdoor is
the OAuth2/OIDC identity provider; the JWT subject is the trust
boundary.

All persistence is inside one compose stack today; cloud-relocation
swap-points are documented for future migration without code changes.

\chapter{Domains and clusters}
\snapdiagram{data-model.tex}

\begin{itemize}
  \item Catalog --- \texttt{games}, \texttt{levels},
        \texttt{scene\_elements}, \texttt{level\_assets},
        \texttt{level\_prerequisites}.
  \item Federation \& access --- \texttt{federation\_modules},
        \texttt{game\_access}, \texttt{game\_launches},
        \texttt{game\_uploads}.
  \item Players --- \texttt{characters}, \texttt{spell\_loadout},
        \texttt{character\_quests}, \texttt{character\_items},
        \texttt{controls}.
  \item Identity --- Casdoor's tenant in Postgres (separate database
        within the same instance).
  \item Audit \& cache --- Cassandra keyspace; movement events +
        state-transition audit log.
\end{itemize}

\chapter{Data lifecycle}
\begin{itemize}
  \item \textbf{Hot} ($\le$ 60 s) --- SSE merge stream, in-process
        \texttt{Sinks.Many}. Lost on restart by design; clients
        re-subscribe.
  \item \textbf{Warm} (minutes) --- Cassandra movement events. Useful
        for cross-pod replay; aged out by TTL.
  \item \textbf{Cold} (durable) --- Postgres rows for catalog,
        characters, quests, uploads, audit summary.
\end{itemize}

Hot is recoverable from Cassandra. Cassandra is recoverable from
Postgres + replay. Postgres is the source of truth.

\chapter{Cross-cutting concerns}
\snapdiagram{game-upload-controller.tex}

\begin{itemize}
  \item \textbf{Auditability} --- every state transition emitted by
        \snapfile{GameStateService} writes to the Cassandra audit log.
  \item \textbf{Reproducibility} ---
        \texttt{game\_launches.version\_dir} snapshots
        \texttt{games.current\_version\_dir} at mint, so an in-flight
        launch keeps reading from its install.
  \item \textbf{Reversibility} ---
        \texttt{game\_uploads.superseded\_at} lets administrators pin
        to a prior version through the admin UI.
  \item \textbf{Consistency} --- \texttt{register.sql} executes inside
        the upload R2DBC transaction; failure rolls everything back.
  \item \textbf{Observability} --- scheduled jobs (Sweeper, Pruner,
        CassandraSync) emit one line per run for log scraping.
  \item \textbf{Rate-limit telemetry} --- the
        \texttt{rate\_limit\_events} Cassandra table holds an
        append-only log of every cross-pod rate-limit decision with a
        90\,s TTL. Aggregates back to per-user / per-zone counters
        without bloating durable state.
\end{itemize}

\chapter{Identity, regulatory, DR}
\begin{itemize}
  \item PII surface: Casdoor user email + display name, stored in
        Casdoor's Postgres; not duplicated.
  \item Auth tokens: issued by Casdoor, verified at the BFF; never
        logged.
  \item Audit log: stores \texttt{casdoor\_user\_id}; combine with
        Casdoor's tenant DB for traceback.
  \item RPO 24 hours (nightly Postgres + uploads-dir snapshot); RTO
        $\sim$30 minutes (compose up against a restored VM).
  \item Right-to-erasure: delete the Casdoor user, cascade to
        \texttt{characters}, NULL out \texttt{casdoor\_user\_id} in
        audit rows.
\end{itemize}

\chapter{Per-game scope tables}
Mod and publisher authorisation is split intentionally:

\begin{itemize}
  \item \textbf{Casdoor} owns ``is a mod / publisher at all'' ---
        \texttt{ROLE\_MOD} / \texttt{ROLE\_PUBLISHER} membership lives
        in the Casdoor tenant.
  \item \textbf{Postgres} owns ``for which games'' ---
        \texttt{mod\_game\_scopes} and \texttt{publisher\_game\_scopes}
        each hold one row per (casdoorId, gameSlug) pair.
\end{itemize}

The BFF reads both layers for every mod- or publisher-only mutation.
A Casdoor token alone authenticates the request but doesn't authorise
it; the Postgres row provides the per-game gate. This means an
identity provider replacement (Auth0, Cognito, Entra) carries the
role membership but the per-game scope stays in your relational
store --- a clean separation for cloud relocation.

Mutation endpoints follow a strict admin / publisher split. Only
\texttt{/api/admin/role-grants/*} (admin) and
\texttt{/api/publisher/grant-mod} (publisher within scope) write
rows; everything else is read-only. The rejection matrix is pinned by
\reposrc{e2e/features/security/mod-grant-gates.feature}.

\chapter{Maker side databases}
The RPG and VN makers each ship as their own Spring Boot side service
with its own Postgres instance. Schemas live under
\snapfile{rpg-builder/src/main/resources/db/changelog/} and
\snapfile{vn-builder/src/main/resources/db/changelog/} respectively
--- managed by Liquibase end-to-end (no JPA \texttt{ddl-auto}, no
psql-init seed file).

\begin{itemize}
  \item \snapfile{postgres-rpg-builder} --- areas, rooms, exits,
        items, NPCs, scripts. Mudlet-shaped.
  \item \snapfile{postgres-vn-builder} --- acts, characters,
        backgrounds, scenes, dialogue lines, branching choices.
        godot-2d-visual-novel-shaped.
  \item Each side service's build worker walks its project tree,
        renders a Godot 4 source tree (with
        \snapfile{snapdragon\_bridge.gdextension} baked in), invokes
        the Godot CLI per area / act, zips the result, and POSTs to
        the BFF \texttt{/api/admin/games/upload} endpoint with the
        originating user's bearer token --- so the BFF's existing
        \texttt{publisher\_game\_scopes} check enforces who can ship
        which slug.
  \item Each area (RPG) or act (VN) becomes a Chapter row in the BFF's
        \texttt{chapters} table on upload. The host portal's
        existing chapter chooser handles multi-chapter games out of
        the box.
\end{itemize}

The three Postgres instances (BFF, RPG builder, VN builder) live in
the same compose stack today but have nothing in common at the
schema level; cloud relocation can move them independently if cost
or scale warrants. See decision 018.

\chapter{Identity widening}
Liquibase 036 widens session-id columns from \texttt{varchar(36)} to
\texttt{varchar(64)} to fit \snapfile{Crypto.mintUid()} output ---
43-character URL-safe base64 of \texttt{SHA3-256(64 random bytes
from BouncyCastle SP800-90A HMAC-SHA256 DRBG)}, replacing
\texttt{UUID.randomUUID()} for every UI-facing UID and URL token.

Implications for the data model:

\begin{itemize}
  \item Pre-existing UUID-shape rows (36 chars) continue to fit ---
        the migration widens, never narrows. No data rewrite.
  \item Cross-system joins on session id keep working because the
        column types match across consuming tables (the migration
        widens every join target in the same changeset).
  \item External integrations that cached session ids assuming a
        36-char shape need a 64-char buffer --- relevant only for
        log shippers or analytics warehouses pulling \texttt{game\_sessions.id}
        without a length-aware schema.
\end{itemize}

The DRBG is a process-singleton, so caller code doesn't need to
thread state. Hashing for non-UID purposes uses
\texttt{Crypto.sha3\_256(...)} from the same module; the wiki
decision document covers the threat model that motivated leaving
\texttt{UUID.randomUUID()} behind.

\chapter{Cloud relocation swap-points}
\begin{itemize}
  \item Postgres $\rightarrow$ managed RDS / Cloud SQL: change
        \texttt{spring.r2dbc.url} + \texttt{spring.datasource.url}.
        No code change.
  \item Postgres read replica $\rightarrow$ Aurora reader / Cloud SQL
        replica: set \texttt{app.r2dbc.replica.url}. No code change
        --- \snapfile{R2dbcReadReplicaConfig} aliases primary when
        empty.
  \item Cassandra $\rightarrow$ managed Astra / Scylla:
        \texttt{spring.cassandra.contact-points}. No code change.
  \item Casdoor $\rightarrow$ managed identity (Auth0 / Cognito /
        Entra): change \texttt{/.well-known/jwks} URL +
        Casdoor-specific role mapping.
  \item Object-storage uploads: \texttt{app.uploads.storage=s3} +
        the four \texttt{APP\_UPLOADS\_S3\_*} knobs (AWS, Cloudflare
        R2, Backblaze B2, MinIO). No code change --- the
        \snapfile{UploadStorage} strategy abstracts the backend.
  \item Streaming audit / telemetry: \texttt{app.kafka.enabled=true}
        + Kafka + ClickHouse bootstrap URLs. No code change ---
        gated producers + consumer.
  \item Federation manifest URL --- already DB-backed; no host
        changes needed.
  \item BFF perimeter --- the \snapfile{snapdragon-gateway}
        (Spring Cloud Gateway) routes \texttt{/api/*} to the BFF and
        carries the primary rate-limit + revocation list; the BFF's
        \snapfile{RateLimitFilter} + \snapfile{RevocationListService}
        mirror as defence-in-depth.
\end{itemize}

\chapter{Shipped --- was ``future'' in earlier versions of this guide}
These items are now in production-shaped state. The data model
didn't need a rewrite to land any of them; each was additive.

\begin{itemize}
  \item \textbf{Streaming audit + telemetry pipeline.} Kafka topics
        \texttt{state\_audit}, \texttt{game\_events},
        \texttt{game\_kpi}, \texttt{session.<id>.events} produced by
        \snapfile{GameAuditPublisher} / \snapfile{GameEventPublisher} /
        \snapfile{GameKpiPublisher}. ClickHouse consumes via
        Kafka-engine + materialised views. Gated by
        \texttt{app.kafka.enabled} (default \texttt{false}). Cross-pod
        consumer + \snapfile{PlayerStateRecoveryService} close the F4
        fan-out loop. Decision 021.
  \item \textbf{Postgres read replica routing.}
        \snapfile{R2dbcReadReplicaConfig} provides
        \texttt{@Qualifier("replica")} beans; compose-level overlay at
        \reposrc{docker-compose.replica.yml}. Decision 022.
  \item \textbf{Object-storage-backed uploads.}
        \snapfile{UploadStorage} strategy with \texttt{filesystem}
        (default) + \texttt{s3}. \texttt{app.uploads.s3.presigned-reads}
        flips \snapfile{AssetController} into 302-to-presigned-URL
        mode so the WASM hot path stays off the BFF. Decision 020.
  \item \textbf{Cross-pod rate-limit storage.}
        \snapfile{DistributedRateLimitService} on Cassandra
        \texttt{rate\_limit\_events} (90s TTL).
  \item \textbf{Per-role accounts schema.} \texttt{accounts.players}
        / \texttt{accounts.producers} / \texttt{accounts.mods}
        (Liquibase 041) populated on player first-touch or producer /
        mod application approval.
\end{itemize}
